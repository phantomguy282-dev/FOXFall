# Implementation Plan — FOXFall 1.0.0 scope (M5 + M6 + Dashboard)

## 0. Release policy alignment (done first)
- CI workflow no longer publishes on tag push; `workflow_dispatch` only, and the
  publish step is gated behind an explicit `PUBLISH_RELEASE=true` variable.
- Internal version drops to **0.9.0-dev** (pre-1.0 by semver, honors the rule
  "do not label incomplete development builds as FOXFall 1.0.0").
- `CHANGELOG.md` records everything shipped so far; v2.x GitHub releases are
  converted to pre-releases and marked as internal development builds.

## 1. Phase A — Backend media core (new `core/mediadb.py`, `backend/server.py`)
- **Library index**: JSON at `<user-data>/config/library.json` — persisted,
  resumable (existing entries skipped unless stale), deduped by absolute path.
- **Scan**: enumerate completed downloads + any user-added folder; for each
  media file run `ffprobe -print_format json -show_format -show_streams`
  (timeout-bounded). Extract duration, resolution, codecs, size, mtime.
- **Thumbnail cache**: `<user-data>/thumbs/<sha1(path+mtime)>.jpg` generated
  with `ffmpeg -ss <10% of duration> -frames:v 1`. Missing/inaccessible files
  are marked `missing: true`, never removed silently.
- **Progress**: scan emits `library_progress` events (scanned/total) so the UI
  never blocks — scanning runs in a daemon thread.
- **Persistence + recovery**: partial scans save their state; a rescan
  continues instead of restarting from zero.

## 2. Phase B — Tools core (backend actions)
- `tool_convert`: ffmpeg `-i in -y out` with `-progress pipe:1` parsed into
  `tool_progress` events; cancellation via process kill + partial-file cleanup
  (only temp files removed — original preserved).
- `tool_extract_audio`: ffmpeg `-vn -acodec` per chosen format
  (mp3/wav/aac/flac), same progress/cancel contract.
- `tool_thumbnail`: ffmpeg `-ss <t> -frames:v 1 out.png|jpg`.
All three write outputs **only** to the user-chosen destination, verify the
output exists and is nonzero before reporting success, and never touch the
input file.

## 3. Phase C — IPC allowlist additions
`library_scan`, `library_status`, `library_list`, `library_remove`,
`library_open_thumb`, `tool_convert_start`, `tool_cancel`, `tool_thumbnail`,
`tool_extract_start`, `tool_pick_output` — all validated, all routed through
the existing preload bridge (no new security surface).

## 4. Phase D — Renderer
- Media Library: real thumbnail grid (cache-served), search/sort/favorites
  (stored in library.json), details view, rescan with progress bar, per-item
  open/reveal/remove; honest missing-file states.
- Media Tools: converter / extractor / thumbnail generator forms wired to the
  backend; progress bars; cancel buttons; Planned tags removed only as each
  ships.
- Dashboard: Recent Activity bound to persistent history (already stored in
  `history.json`), refreshed on `download_finished` and backend `ready`
  events; entries whose files vanished show an unavailable state.

## 5. Phase E — Tests
- pytest: library index dedupe/persistence/missing-file handling; thumbnail
  cache path stability; tool output verification with a tiny generated media
  file (ffmpeg `testsrc`).
- Node IPC: new actions answered; malformed payload rejected.
- Manual/CDP: installed-app rescan with real files, tools run against a real
  video, dashboard shows persisted activity after restart.
